# 术语词典内置词库说明（lexicon / stopwords）

## 这些文件是做什么的

`lib/lexicon.en.js`、`lib/lexicon.zh.js`、`lib/stopwords.js` 是插件离线识别术语的**纯数据层**：
不联网、不做任何逻辑，由浏览器打包表与 Node 测试共同加载。检测器命中词库即直接给出中文释义，
未命中才走模型兜底；词库同时用于过滤，避免把日常词误判成专业术语。

## 数据格式（三个文件都必须遵守）

```js
module.exports = {
  "<键>": { zh: "中文译名", domain: "领域标签", gloss: "一句中文解释" },
};
```

- `zh`：中文译名。英文词库要求 2–8 个汉字、不含英文数字；中文词库要求 3–8 个汉字的口语化改写。
- `domain`：只能取 `计算机`、`软件工程`、`人工智能`、`数据`、`网络`、`安全`、`运维`、`数学`、`系统`、`产品`。
- `gloss`：一句话讲清“它是什么”，面向不懂该术语的聪明读者；不解释词源，实测长度 15–31 汉字。
- 英文键一律小写 ASCII，只允许单个空格、连字符、点；中文键为 2–6 个汉字。
- 三个文件都必须是 CommonJS（`"use strict";` + `module.exports`），**不得出现** `import`/`export`/`require`，
  也不得有任何副作用代码——浏览器打包表需要可直接取用的 `module.exports` 值。

## 如何新增词条

1. 在对应文件的对象里加一行，键按上文规则写，`zh`/`domain`/`gloss` 三个字段缺一不可。
2. 放入文件时保持“一行一条”，便于 diff；大小写、错别字、重复键都会让检测静默失效，务必自查。
3. 日常词、代词、介词、动词不要进 lexicon，应进 `stopwords.js` 的 `EN`/`ZH` 数组。
4. 两个数组必须**去重并排序**（`EN` 按字典序，`ZH` 按码点序），新增后重新排序。
5. 改完必须跑一遍校验：条目数、三字段非空、重复键、数组重复、键大小写。

> 注意：`lib/package.json` 里的 `{"type":"commonjs"}` 是作用域标记，缺了它 Node 会按外层
> `package.json` 的 `"type": "module"` 把这些 `.js` 当 ESM，`require` 将取不到词条。

## 明显偏薄、下一步应扩的区域

- **英文**：网络（20）与产品（7）远低于其他板块，需要补 HTTP/TCP 细节、云网络、增长与商业化术语。
- **英文缺口领域**：编译原理与链接细节、数据库存储引擎内部、计算机体系结构与指令集、图形学与音视频编解码、
  量化金融、生物信息、硬件与嵌入式。这些目前基本没覆盖。
- **中文**：网络（3）、安全（2）、计算机（2）几乎没有；另缺医疗、金融、法律、汽车制造、游戏、政务等行业黑话。
- **中文缺口形态**：多为运维/架构/产品口径的互联网黑话，缺少传统行业术语与地方性缩写。
- **停用词**：`EN` 尚未覆盖专有名词、人名地名与缩写黑名单；`ZH` 还缺大量常见二字词、姓氏与机构名，
  后续应按真实语料高频词补齐，而不是凭印象堆量。
